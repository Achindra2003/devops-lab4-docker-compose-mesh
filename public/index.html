Storage Tier Validation & Persistence

Testing Named Volume recovery, Read-Only Bind Mounts & Tmpfs
PERSISTENT VOLUME
redis_data (Named Volume)
Target: /data inside mesh-cache
Append-Only File (AOF) ensures zero data loss even if container is destroyed via docker compose down.
Records in Volume: 0
READ-ONLY BIND MOUNT
./nginx/nginx.conf
Mount: /etc/nginx/nginx.conf:ro
Injects immutable gateway configuration from host without baking files into image layers. :ro prevents tampering.
IN-MEMORY TMPFS
tmpfs: /tmp (64MB)
Mount: /tmp inside mesh-api
High-speed RAM-backed storage for ephemeral security tokens. Never touches physical disk.

Architectural Benchmark: Naive Compose vs. Production MeshPulse

Comparing network isolation, storage durability, security posture, and lifecycle healthchecks

DevOps Best Practice Contrast
UNOPTIMIZED (BASELINE)
docker-compose.unoptimized.yml
Network Topology: Single flat bridge (Zero isolation) ⚠️
Database Exposure: Redis exposed to gateway & ingress
Storage Durability: Ephemeral (100% data loss on down)
Security Privileges: root (UID 0) across all services
Service Orchestration: No healthchecks (Race conditions)
Resource Limits: Uncapped (Noisy Neighbor hazard)
PRODUCTION (MESHPULSE)
docker-compose.yml
Network Topology: Dual subnets (frontend-net & backend-net) ✔
Database Exposure: Isolated on backend-net (Zero-Trust) ✔
Storage Durability: Named Volume redis_data with AOF ✔
Security Privileges: USER node (UID 1000) & no-new-privileges ✔
Service Orchestration: depends_on: condition: service_healthy ✔
Resource Limits: Capped (CPU: 0.5, RAM: 128M - 256M) ✔
